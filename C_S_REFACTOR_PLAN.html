01
Overview

总览

App Process
MobileGL_Client
thin API shim · trampoline · transport · shm client
⇄
Big Server Process
FullServer
MG_Impl · MG_State · BFA Host · plugin loader · session routing
⇄
Plugin .so
BackendObject
DirectGLES / DirectVulkan · native GPU state
正确切点 = 公开 EGL/GL API；不是 BackendObject 接口。Final 只保留 C/S 产物，无 monolith。
边界 1

Client ⇄ BigServer

FlatBuffers + 本地 socket + Server 管理 shm arena；全量 API codegen。

边界 2

FullServer ⇄ Backend

BFA：strict C ABI、handle/session/generation、独立版本化插件。

边界 3

FullServer/Backend ⇄ UtilRuntime

MG_Util 全量 C ABI；根 MobileGLUtilApi + 分域 sub-vtable，Host 注入。

背景 · 现状问题（原 MD §1.2）
当前所有代码编译进同一个 MobileGL.so / MobileGL_s.a（CMakeLists.txt:483-582）
MG_Impl / MG_State / MG_Util / MG_Backend 全部耦合在一个库中
BackendObject 已是中间层雏形，但为进程内 C++ 多态接口
  - 函数参数含 SharedPtr<MG_State::...>（BackendObject.h:158-188）
  - 后端直接读取全局 MG_State::pGLContext（数百处）
  - 后端状态是进程全局（pVulkanRenderer / g_activeBufferManager / g_GLESFuncs）
  - pGLContext 是进程级单例（GLState/Core.cpp:20），不支持多 context

核心判断（原 MD §1.3）：
  正确的 C/S 切点 = 公开 EGL/GL API，而不是 BackendObject 接口
  Server 侧运行完整现有 frontend + 一个 BackendObject
  "Server(per BackendObject) 单独 target" 落地为：每个 BackendObject 一个独立插件 .so target

04
Unified Semantics

Handle · Session · Generation

DisplayId
一个 EGLDisplay
支持多个 Display
SharedGroupId
share context 组
共享对象表：buffer / texture / VAO / program / sampler / FBO / RBO / TF
SessionId
一个 EGLContext
current bindings · render state · error queue · default 对象
ObjectHandle
uint64 不透明句柄
共享对象 per SharedGroup；上下文私有对象 per Session
Generation 来源

已有机制直接映射

  • Texture：shape / content / params / bind / sampling
  • Program：link / backendState / uniform / UBO / block
  • VAO：config / attribute；FBO：object / attachment
  • RenderState：version / pipelineVersion
缓存 key

Backend 缓存失效

{ SharedGroupId, ObjectHandle, objectGeneration }

后端缓存与 native resource 全部搬进 backend 内部 map，不再写回 frontend 对象。

缺口 1

pGLContext 单例

GLState/Core.cpp:20 唯一创建点 → 拆成 GLSharedGroup + GLContextSession

缺口 2

shareCtx 空壳

仅存于 EGLState，GLState 从未使用 → 完整 share group 需新增实现

缺口 3

Backend 全局单体

pVulkanRenderer / g_activeBufferManager → per-display / per-group / per-session

归属规则 · Handle 映射 · Generation 明细（原 MD §5）
归属规则:
  EGL display / config / surface            → DisplayId
  共享对象表(buffer/texture/VAO/program/sampler/FBO/RBO/TF) → SharedGroupId
  上下文私有对象(default FBO/VAO/texture 0、query、sync)    → SessionId
  current bindings / render state / error queue             → SessionId
  backend native 共享资源(VkBuffer/VkImage/pipeline/sampler) → SharedGroupId
  command pool / descriptor pool / frame / deferred release  → SessionId
  硬件设备 / loader                                           → DisplayId

Handle 映射:
  共享对象    (SharedGroupId, ObjectKind, GLname) → handle
  上下文私有  (SessionId, ObjectKind, name/slot)  → handle
  ObjectHandle = uint64_t，FullServer 分配，进程生命周期内不复用

Generation 映射（现有机制直接投影）:
  GetShapeVersion / GetContentVersion / GetTextureParamsVersion
      → TextureInfo.generation / contentGeneration / paramsGeneration
  GetTextureBindGeneration / GetSamplingResolutionGeneration
      → TextureInfo.bindGeneration / samplingGeneration
  GetRenderStateParametersVersion / GetPipelineStateVersion
      → RenderState.version / pipelineVersion
  GetLinkVersion / GetBackendStateVersion / GetUniformWriteSetVersion
      → ProgramInfo.linkGeneration / backendStateGeneration / uniformWriteGeneration
  GetConfigVersion / GetAttributeVersion
      → VertexArrayInfo.generation / attribs[].generation
  GetObjectVersion / GetAllFramebufferAttachmentVersions
      → FramebufferInfo.generation
  SamplerObject::GetVersion / GetTransformFeedbackGeneration
      → SamplerInfo.generation / TransformFeedbackInfo.generation

Backend 缓存 key: { SharedGroupId, ObjectHandle, objectGeneration }

Execution

语义同步 · 执行异步

无响应命令批量流水线；查询与同步点为 barrier。

Shm

Server-managed arena

FullServer 分配/复用/引用计数；Client mmap 读写。

FlatBuffers 消息结构
union Payload { EglInitialize, EglCreateContext, GlDrawArrays, GlReadPixels, GlMapBufferRange, ... }

table Command {
  sessionId: ulong;
  clientThreadId: uint;
  seq: uint;
  flags: uint;
  opcode: ushort;
  payload: Payload;
  payloadShm: ShmRegion;
}

table Message { version: uint; command: Command; }
数据通路 / map / readback
glBufferData / glTexImage2D / shader source
  → Client 写 shm payload → Server 读取

glReadPixels / glGetTexImage / glGetIntegerv
  → Server 写 shm → Client 读取

glMapBufferRange
  → Server 分配/复用映射区域 → Response 带回 → Client 返回 64 对齐指针

glGetString
  → Server 稳定字符串 → Client thread_local 缓存
Transport 抽象（原 MD §6.1）
typedef struct MobileGLTransportOps {
  uint32_t structSize;
  bool (*Start)(MobileGLTransport* t, const MobileGLTransportConfig* cfg);
  void (*Shutdown)(MobileGLTransport* t);
  bool (*SubmitCommands)(MobileGLTransport* t, MobileGLCommandBatch* batch);
  bool (*WaitResponses)(MobileGLTransport* t, MobileGLResponseQueue* out, uint32_t timeoutMs);
  bool (*OpenSharedMemory)(MobileGLTransport* t, MobileGLShmHandle* out);
} MobileGLTransportOps;

实现: LocalSocketShm(v1) / InProcess(测试) / RemoteTcp(后续) / AndroidBinder(后续)
API codegen 管线（原 MD §6.3）
输入 API 清单（name / signature / category / alias）
  1. protocol.fbs 生成（统一 Message + union payload）
  2. opcode 表生成（name→opcode，alias→core opcode）
  3. client trampoline 生成（FlatBuffer + shm）
  4. server dispatch 生成（解析 → 调用 MG_Impl）
  5. 函数分类表生成

分类:
  VOID           glDrawArrays/glBindTexture → 无 response
  GETTER         glGetIntegerv              → request + response
  POINTER_RETURN glGetString/glMapBufferRange → response 返回 shm 区域/稳定指针
  ARRAY_OUT      glGenTextures              → response 带 names
  MAP/UNMAP      glMapBufferRange/glUnmapBuffer → 专用数据流 + client 映射表
执行模型明细（原 MD §6.5）
CommandBatch（异步提交）
  ├── 无响应命令: glDraw / glBind / glTexParameter...
  └── 查询/barrier 命令: 带 seq，等 response

ResponseQueue（同步等待）

同步点标准语义:
  glFlush       = flush command ring（不等待执行完成）
  glFinish      = flush + barrier ack（等待之前命令全部完成）
  eglSwapBuffers= flush + present 完成 ack
  所有查询命令 = 天然 barrier

顺序保证:
  同一 (sessionId, clientThreadId) 流严格 FIFO
  不同线程/不同 session 可交错执行
Client Token 模型与会话生命周期（原 MD §6.8-6.9）
Client 不维护 GL 状态；只透传 server 返回的 token
eglGetDisplay(native) → server 返回 displayToken
eglInitialize → 初始化 display
eglBindAPI / eglChooseConfig / eglCreateContext
  - 无 shareCtx → 新建 SharedGroupId
  - 有 shareCtx → 加入其 SharedGroupId
eglMakeCurrent → 写 (sessionId, clientThreadId) → current
glXxx / eglSwapBuffers / glFinish ...
eglDestroyContext / eglTerminate → 清理 session/group/display

eglGetProcAddress: 仅已知 codegen API 返回 client trampoline；未知返回 NULL

Snapshot 结构与数据通路（原 MD §7.5-7.6）
MobileGLSessionDrawState:
  当前 program/pipeline/VAO/FBO + buffer/texture/sampler/image 绑定 + draw/renderState 版本

对象 Info（POD + structSize + generation）:
  BufferInfo / TextureInfo / FramebufferInfo / VertexArrayInfo
  SamplerInfo / ProgramInfo / RenderbufferInfo
  MobileGLProgramStageModule: 每 stage SPIR-V 指针 + 大小 + entryPoint + generation

Capabilities:
  RendererInfo            = POD + plugin-owned 字符串指针 + 扩展数组
  DynamicBackendParameters= POD 按值/指针
  FormatCapabilityCache   = 固定掩码 POD；可变 SampleCounts 两段式查询

数据通路:
  Buffer shadow        Host_GetBufferShadow（调用期有效，必须 copy）
  Buffer range         Host_ReadBufferRange
  Texture mip          Host_GetTextureMipInfo + Host_GetTextureMipData
  Program 模块         Host_GetProgramModules（SPIR-V 指针）
  Persistent map       BackendVTable::BufferAcquirePersistentMap 返回 GPU 映射指针

v1 不做 dirty-rect 增量：generation 变了就整级/整对象重传
BFA 线程 · 生命周期 · 错误 · 版本（原 MD §7.8-7.9）
线程:
  同一 session 的 backend 调用串行
  不同 session 并发，Host 查询线程安全
  v1 禁止 backend 自建线程回调 Host

生命周期:
  OnObjectDestroyed 显式通知，替代基于 WeakPtr 的隐式 GC
  backend 错误通过 Host_RecordError 上报，错误队列仍由 frontend 持有

ABI/版本:
  所有 table 有 structSize + apiVersion
  尾部加字段 = minor 兼容；修改语义/删除 = major
  加载失败不得抛异常，返回结构化错误

Risks

风险与对策

GLContext 拆分 + Share GroupHigh

单例 + shareCtx 未实现，最重重构。对策：先对象表共享，再补删除传播。

Multi-display 全局态High

pVulkanRenderer 等需 per-device。对策：Device / Group / Session 三层。

全量 MG_Util C ABIMid

覆盖广。对策：分域 sub-vtable + codegen + 独立演进。

FlatBuffers codegenMid

flatc 进构建。对策：API 单源，CI 校验生成物。

异步协议正确性Mid

顺序/错误/响应。对策：seq + 每流 FIFO + contract tests。

测试迁移Mid

现有测试直连 gBackendFunctionsTable / pGLContext。对策：mock BFA / Runtime / transport。

共享 Runtime ABIMid

插件与 runtime 独立版本。对策：Host 注入 RuntimeApi；插件不链接 runtime。
